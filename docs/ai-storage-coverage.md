# AI and agent storage

The bundled Developer module detects agent history, file checkpoints and model downloads in Opportunities. Tool breakdowns use the completed scan's metadata only: no transcript/database/model content reads, tool execution, environment-variable reads or extra disk traversal. This is a practical selection of widely used tools, not a measured popularity ranking.

All AI findings require review. Complete Hugging Face and LM Studio repositories can use the in-app Recycle Bin review. Whole Codex history/log folders, Claude project/debug folders and Gemini chat folders stay **kept**; use **Extensions → Agent cleanup** for individual old transcripts and logs. The shared Ollama library and application stores that contain credentials remain **kept**, including through selected ancestors; individual Ollama models use the **AI models** workflow. Restrictions are rediscovered during preparation and execution. An observed size is not guaranteed recovery. Nested findings count once within a group; groups can overlap.

The top **Detected storage** total includes kept stores. Only eligible cleanup checkboxes are enabled. See [in-app cleanup and confirmation](containers-and-wsl.md) for model, Docker and disk actions.

## Clean up old sessions and agent leftovers

Open **Extensions → Agent cleanup → Files & Cursor CLI → Inspect history**. The default is items last changed at least 30 days ago. Filter by tool; a blank custom home searches all its standard locations, or choose a relocated agent/extension home. Inspection reads names/native metadata and bounded Roo task-status metadata, never conversation contents. The list shows supported files or whole Cursor CLI folders with their dates and logical sizes. Nothing is automatically selected. Unsupported, recent, linked, cloud-managed and hard-linked data stays in place. Limits and inaccessible paths are visible in status/details.

Select up to 500 items and choose **Review cleanup**. The preview lists exact paths and scope; Cursor folders have an expandable complete content list. Stop clients, editor hosts and background agents, preserve needed history and acknowledge this before confirming. Space Maid rechecks native identity, size, timestamps, age and layout. Copilot/Cline/Roo session activity also covers related files and directories (up to 1,000 entries), so a new plan, artifact or lock keeps the task. Known owner processes block preparation and execution; Cline hub owner registrations and Roo task relationships add further protection.

File recycling holds write-denying leases. Whole Cursor folders are validated under leases immediately before native execution and again at Windows' root-delete callback, then leases are released because Windows cannot recycle a folder while those handles remain held. Windows must confirm the exact root's Recycle Bin destination; permanent deletion is refused. Restarted or unrecognized clients and new names remain live-system races, so the stopped-clients acknowledgment matters. Cancellation stops remaining items; already moved items stay in the bin. Uncertain results require another inspection before retrying.

Loose-file rows remove the selected **transcripts or logs**, rather than complete sessions in the owning app. Codex/Gemini indexes, related artifacts, Claude memory/subagent sidecars, checkpoints and credentials are kept. An app may continue showing a history entry whose transcript is gone. Restore from the Recycle Bin if needed; app-level session recovery is not guaranteed. File age does not prove a session is finished, pinned or unwanted, and Space Maid does not inspect app session databases to infer that state. Sources: [Codex application storage](https://learn.chatgpt.com/docs/reference/troubleshooting), [Claude application data](https://code.claude.com/docs/en/claude-directory), [Gemini session management](https://geminicli.com/docs/cli/session-management/).

**Cursor CLI folders** are the complete local chat recovery unit, including `store.db`, WAL/SHM sidecars and every listed file. They are recycled together, preserving separate credentials, editor databases and transcript mirrors outside that folder. **Roo interrupted-write leftovers** can contain recovery data, so their preview warns about that loss; missing canonical files or unverified task status keep them protected.

For **OpenCode sessions**, use the separate tab. Start your local OpenCode server yourself (`opencode serve`, default `127.0.0.1:4096`) and inspect its current project. A configured password is optional, in-memory only, with default username `opencode`. The app uses the verified version-1 `/session` API on this fixed loopback endpoint with no proxies, redirects or remote host settings. Unsupported versions and incomplete/oversized reports fail closed. No server or tool is installed or started automatically.

Review one old, idle, unshared, unmanaged session with no parent or children. The exact ID, title, project and last change appear before a **permanent-delete** confirmation and paused-clients acknowledgment. The server, project identity, session metadata, idle status and absence of children are checked again before DELETE. The server must confirm deletion and subsequent absence. Activity belongs to that serving instance: pause all OpenCode clients and automation, including other instances. Its API cannot atomically check idle state and delete. Uncertain requests are not retried. Database free pages can remain allocated, so disk recovery is unknown. The API path does not delete shared sessions or manipulate credentials, databases, workspace files or cloud copies directly.

For stale agent worktrees, scan their containing folder in **Opportunities**, open **Worktrees** and choose **Check worktrees**. The default requires clean Git status, local integration and 30 days without observed file/reflog changes. Detached checkouts are supported when their HEAD is contained in the cached remote default, or local `main`/`master` if no remote default is available. Detached commits outside that branch stay protected in every age mode. Changed, untracked, locked, submodule and unresolved checkouts stay protected. No fetch is performed, so integration uses local evidence. [Git worktree documentation](https://git-scm.com/docs/git-worktree) explains detached registrations and recovery.

Review the matched exact folders and confirm in-app recycling. Stop agents, editors and builds first; the preview warns that ignored files are included and can contain unique data. Worktree rules and current Git status are checked again before execution. Branches, shared Git storage and registration stay in place for recovery; restoring the folder to its original path can reconnect it. This does not prune registrations or remove branches. Old named branches can use the existing age-only rule because their commits remain in their branch; detached work must already be integrated.

## Limits

Opportunity detection is scoped to the selected scan and visible metadata. Conventional paths require their owning ancestors in the inventory. Custom homes, editor profiles and LM Studio roots are not inferred from environment/configuration. Agent cleanup separately inspects standard or explicitly chosen homes, bounded to 20,000 discovered entries and a one-minute deadline; individual session/folder checks stop at 1,000 entries. Known process names help protect active work but do not prove all clients are stopped. Cursor IDE shared chat databases remain protected; only its standalone CLI folders have a verified whole-session filesystem contract. [Containers and WSL coverage](containers-and-wsl.md) describes the other storage actions. RAG/vector databases, generic model files and partial model downloads have no new cleanup rule. Space Maid does not compact databases or change tool retention settings. Tests use owned temporary files and simulated API responses, never personal agent data or live session deletion.
