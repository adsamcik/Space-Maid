# AI and agent storage

The bundled Developer module detects agent history, file checkpoints and model downloads in Opportunities. Tool breakdowns use the completed scan's metadata only: no transcript/database/model content reads, tool execution, environment-variable reads or extra disk traversal. This is a practical selection of widely used tools, not a measured popularity ranking.

All AI findings require review. Model libraries and shared application stores are **kept**: Space Maid displays their observed size and tool-specific advice, but blocks recycling, including through a selected ancestor. These restrictions are rediscovered during preparation and execution. An observed size is not an estimate of space the owning tool can release. Nested findings count once within a group; groups can overlap.

The top **Detected storage** total includes kept stores. Their cleanup checkboxes are disabled at folder, tool and group levels; they remain browsable for sizes, exact paths and guidance.

Existing Node/Python dependency, uv/pip/npm cache, build-output and Playwright browser/report detectors also cover common agent-driven installs, builds and browser testing. Worktree containers are never treated as disposable merely because of their name or age.

## Limits

Detection is scoped to the selected scan and visible metadata. Conventional agent paths require their owning ancestors in the inventory. Relocated Hugging Face and Ollama stores have recognizable layouts; arbitrary custom agent homes, editor profiles and LM Studio roots are not inferred from environment or configuration. [Containers and WSL coverage](containers-and-wsl.md) adds protected backing disks, local Docker inspection and cleanup guidance. RAG/vector databases, generic model files and incomplete model downloads have no new cleanup rule. Application processes, actual model use and download activity are not checked. Space Maid does not compact databases, execute suggested commands, change retention settings or remove real AI-tool data during detection or tests.

Release build passed with zero warnings on Windows/.NET 10. The suite and affected reruns together passed 426 distinct tests; three administrator-only checks were skipped. The final 37-test rerun included detection, grouping, extension loading and the complete WPF workflow. Preparation and execution tests preserve managed stores and selected ancestors even when restrictions appear after confirmation. Rendered light/dark 1220×910 and compact 1020×790 views were inspected using illustrative metadata, with model browsing and disabled cleanup controls exercised. An independent review's two presentation findings were addressed. These checks do not establish real-account integration or actual model/cache reclamation.
