# AI and agent storage

The bundled Developer module detects agent history, file checkpoints and model downloads in Opportunities. Tool breakdowns use the completed scan's metadata only: no transcript/database/model content reads, tool execution, environment-variable reads or extra disk traversal. This is a practical selection of widely used tools, not a measured popularity ranking.

All AI findings require review. Complete Hugging Face and LM Studio repositories can use the in-app Recycle Bin review. Whole Codex history/log folders, Claude project/debug folders and Gemini chat folders stay **kept**; use **Extensions → Agent cleanup** for individual old transcripts and logs. The shared Ollama library and application stores that contain credentials remain **kept**, including through selected ancestors; individual Ollama models use the **AI models** workflow. Restrictions are rediscovered during preparation and execution. An observed size is not guaranteed recovery. Nested findings count once within a group; groups can overlap.

The top **Detected storage** total includes kept stores. Only eligible cleanup checkboxes are enabled. See [in-app cleanup and confirmation](containers-and-wsl.md) for model, Docker and disk actions.

## Clean up old sessions and agent leftovers

Open **Extensions → Agent cleanup → Inspect history**. The default is files last changed at least 30 days ago; change the age or select one agent and choose its relocated home folder. Inspection reads names and metadata, never conversation contents. The list shows exact supported transcript/log files and their dates and logical sizes. Nothing is automatically selected. Unsupported, recent, linked, cloud-managed and hard-linked files stay in place. Inspection limits and inaccessible paths are visible in the status/details.

Select up to 500 files and choose **Review cleanup**. The preview lists every exact path and the consequences. Close all clients using these agent homes, preserve needed history and acknowledge this before confirming. Space Maid rechecks native file identity, size, modification time, age and supported layout. The native recycler holds file leases that deny writers and pins parent paths; Windows must confirm a Recycle Bin destination. Permanent deletion is refused. Cancellation stops remaining files; already moved files remain in the bin, and uncertain results require another inspection before retrying.

This removes the selected **transcripts or logs**, not complete sessions in the owning app. Codex/Gemini indexes, related artifacts, Claude memory/subagent sidecars, checkpoints and credentials are kept. An app may continue showing a history entry whose transcript is gone. Restore from the Recycle Bin if needed; app-level session recovery is not guaranteed. File age does not prove a session is finished, pinned or unwanted, and Space Maid does not inspect app session databases to infer that state. Sources: [Codex application storage](https://learn.chatgpt.com/docs/reference/troubleshooting), [Claude application data](https://code.claude.com/docs/en/claude-directory), [Gemini session management](https://geminicli.com/docs/cli/session-management/).

For stale agent worktrees, scan their containing folder in **Opportunities**, open **Worktrees** and choose **Check worktrees**. The default requires clean Git status, local integration and 30 days without observed file/reflog changes. Detached checkouts are supported when their HEAD is contained in the cached remote default, or local `main`/`master` if no remote default is available. Detached commits outside that branch stay protected in every age mode. Changed, untracked, locked, submodule and unresolved checkouts stay protected. No fetch is performed, so integration uses local evidence. [Git worktree documentation](https://git-scm.com/docs/git-worktree) explains detached registrations and recovery.

Review the matched exact folders and confirm in-app recycling. Stop agents, editors and builds first; the preview warns that ignored files are included and can contain unique data. Worktree rules and current Git status are checked again before execution. Branches, shared Git storage and registration stay in place for recovery; restoring the folder to its original path can reconnect it. This does not prune registrations or remove branches. Old named branches can use the existing age-only rule because their commits remain in their branch; detached work must already be integrated.

## Limits

Opportunity detection is scoped to the selected scan and visible metadata. Conventional agent paths require their owning ancestors in the inventory. Relocated Hugging Face and Ollama stores have recognizable layouts; arbitrary custom homes, editor profiles and LM Studio roots are not inferred from environment or configuration. Agent cleanup separately inspects standard homes or an explicitly chosen relocated home using bounded native file metadata. [Containers and WSL coverage](containers-and-wsl.md) adds protected backing disks, local Docker inspection and cleanup guidance. RAG/vector databases, generic model files and incomplete model downloads have no new cleanup rule. Application processes are not inspected to infer session activity. Space Maid does not compact databases or change tool retention settings. Detection and tests never remove personal AI-tool data; native recycling tests use owned temporary files.
